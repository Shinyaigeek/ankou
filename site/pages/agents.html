Agents

Built to be called by something else

Half the point of ankou is embedding it. An agent already knows what the user asked for — that sentence is the intent — and what comes back is typed JSON, not a blob of prose it has to re-read.

why it fits

A Piece is plain JSON

Persist it, cache it, send it to a browser, hand it to the next agent. It is smaller than the HTML, it is queryable, and every other renderer is one pure call away.

why it fits

Rendering never calls a model

render() is a pure function: no model, no network, safe to run on a server for every request. Decide the shape once, serve it a thousand times.

why it fits

The decision is cheap and separable

carvePlan() is one small call: the format it would pick and the rationale, in the user's language. Show it, route on it, or price the job before committing to it.

The shape of it

One tool, three arguments

Sources, the user's own words, and optionally a format if they were specific ("make me a quiz"). Leave the format out and the planner decides.

FORMAT_IDS is exported, so the enum in your tool schema is generated from the same registry the planner reads — a format added to ankou shows up in your tool definition on the next release rather than after you remember to update a list.

import { carveAndRender, FORMAT_IDS } from 'ankou-core'

export const readTool = {
  name: 'reshape_document',
  description:
    'Reshape one or more documents (markdown, text, HTML, PDF, URL) into the ' +
    'form the user wants to consume them in. Returns a self-contained HTML page.',
  parameters: {
    type: 'object',
    properties: {
      sources: { type: 'array', items: { type: 'string' } },
      intent: { type: 'string', description: "What the user wants out of it, in their words." },
      format: { type: 'string', enum: FORMAT_IDS, description: 'Optional; omit to let ankou choose.' },
    },
    required: ['sources', 'intent'],
  },

  async run({ sources, intent, format }, { signal }) {
    const { piece, plan, output } = await carveAndRender({
      sources,
      intent,
      ...(format ? { format } : {}),
      renderer: 'html',
      signal,
    })
    return {
      format: piece.format,
      rationale: plan.rationale,  // show the user why this shape
      html: output.content,
      piece,                      // keep it: re-rendering is free
    }
  },
}

Four things worth doing

Notes from wiring it in

  1. Reuse the host's model

    Pass llm rather than provider and ankou bills, rate-limits and retries through the same client as the rest of your app — one place to put your keys, one place to watch your spend. 

    await carve({ sources, intent, llm: myAgentsModel })

  2. Store the Piece, not the page

    The user asks for the deck on their phone, then the quiz in the terminal, then the JSON for another tool. That is three renders of one model call. 

    const { piece } = await carve({ sources, intent })
await db.pieces.put(id, piece)

render(piece, 'html', { theme: 'dark' })   // { content, ext, mime }
render(piece, 'tui', { columns: 100 })     // a plain transcript
render(piece, 'json')

  3. Report progress, and mean the cancel button

    A 200-page PDF is windowed and takes a while. onProgress reports the stage — ingest, plan, compose, render — and which window compose is on, so your UI can say something true. An AbortSignal stops the run mid-flight, including the request already in the air. 

    const controller = new AbortController()

await carve({
  sources,
  intent,
  signal: controller.signal,
  onProgress: ({ stage, message }) => ui.status(`${stage}: ${message}`),
})

  4. Let the errors do the talking

    Everything ankou throws deliberately is a AnkouError with a code — INGEST, LLM, COMPOSE, CONFIG — and usually a hint that says what to do about it. An agent can branch on the code and pass the hint straight to the user instead of inventing an explanation. 

    try {
  await carve({ sources, intent })
} catch (error) {
  if (error instanceof AnkouError) reply(`${error.message} ${error.hint ?? ''}`)
  else throw error
}

No SDK required

Or just shell out

An agent that already runs commands does not need a dependency. The CLI writes the piece to stdout, takes stdin as a source, and stays quiet when asked. 

# decide first — one cheap call, nothing generated
ankou paper.pdf -i "$USER_ASK" --plan-only -q

# then generate, and keep the structure
ankou paper.pdf -i "$USER_ASK" --render json -o - -q > piece.json

# render it anywhere later, no model, no network
ankou render piece.json --render html -o out.html

# pipe a document straight in
cat draft.md | ankou - -i "make it land" -f animation --open

-q silences progress so stdout is only ever the artefact. Exit codes and the error hints come through on stderr.

On a developer's machine

A coding agent needs no key

--provider claude-code runs generation through the Claude Agent SDK and authenticates with a Claude Code subscription — so an agent working in someone's checkout can carve a spec without asking them to provision credentials first. 

npm i @anthropic-ai/claude-agent-sdk
ankou ./RFC.md -i "review this properly" -p claude-code --open

The repository also ships a Claude Code skill at .claude/skills/ankou/SKILL.md: it knows to build first, to pick the provider deliberately, and to check the output rather than declare victory when the command exits 0.

Intent is the interface. Do not translate the user's request into your own words before passing it in — the planner reads intent for tone, language and purpose, and answers in the language they used.
