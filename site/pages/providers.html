Models

Bring the model you already have

ankou ships no model and no vendor SDK. Every built-in provider is a fetch call to an endpoint you control — four of them out of the box, and a two-method interface if yours is not one of the four.

ProviderWhat it needsDefault modelGood for
anthropic ANTHROPIC_API_KEY claude-sonnet-5 The default. Native tool-use for structured output.
claude-code A Claude Code subscription and @anthropic-ai/claude-agent-sdk claude-sonnet-5 No API key at all — bills through the subscription you have.
openai OPENAI_API_KEY, or a --base-url for a local server gpt-4.1 OpenAI, OpenRouter, Together, Groq, LM Studio, vLLM — anything speaking /chat/completions.
ollama A daemon at OLLAMA_HOST (default 127.0.0.1:11434) qwen3:8b Local, free, no network egress. The quickest route with no key.

Start with ankou providers

It reports what each provider needs and whether it has it — probing the Ollama daemon rather than assuming it, because "installed but not running" is the case you cannot diagnose from the outside. This is where to land when a run stops for want of a model. 

$ ankou providers

  ✓ anthropic    claude-sonnet-5
      ANTHROPIC_API_KEY
  · openai       gpt-4.1
      OPENAI_API_KEY is not set
  ✓ ollama       qwen3:8b
      a daemon at http://127.0.0.1:11434
  · claude-code  claude-sonnet-5
      run `npm i @anthropic-ai/claude-agent-sdk`

  Try: ankou <source> -i "…" --provider anthropic

Or no provider at all. Over MCP the host is the model: ankou hands each generation back to the agent driving it, and nothing on this page applies. These four are for the CLI and the SDK — the paths where ankou does the asking.

Picked without being told: ANKOU_PROVIDER first, then whichever API key is present — Anthropic, then OpenAI — then OLLAMA_HOST if you pointed it somewhere. A daemon on the default port stays opt-in, because guessing would mean a blocking probe on every run. If nothing is found, the error says so and what to do about it.

Recipes

Wiring each one up

anthropic

An API key

export ANTHROPIC_API_KEY=sk-ant-...
ankou spec.md -i "覚えたい"

# a different model, or a gateway
ankou spec.md -i "…" -m claude-opus-4-5
export ANTHROPIC_BASE_URL=https://my-gateway

Talks to the Messages API directly over fetch — deliberately not the vendor SDK, so ankou-core stays dependency-free and drops into any Node 22 project. Schemas go through native tool use.

claude-code

A subscription, no key

npm i @anthropic-ai/claude-agent-sdk
ankou spec.md -i "覚えたい" --provider claude-code

Generation runs through the Claude Agent SDK, which authenticates with your Claude Code subscription. The SDK is an optional peer, imported lazily, so anyone who only uses API providers never pays for it. Tools are disabled and the turn limit is low — ankou wants a completion, not an agent loop.

openai-compatible

One endpoint, many vendors

# OpenAI
export OPENAI_API_KEY=sk-...
ankou post.md -i "…" -p openai

# OpenRouter / Groq / Together: same shape
ankou post.md -i "…" -p openai \
  --base-url https://openrouter.ai/api/v1 \
  -m anthropic/claude-sonnet-4.5

# LM Studio or vLLM on the desk next to you
ankou post.md -i "…" -p openai \
  --base-url http://localhost:1234/v1 -m local-model

Local servers accept any key, so ankou only insists on one when the base URL is still api.openai.com. Structured output uses the provider's JSON schema mode where it is offered.

ollama

Nothing leaves the machine

ollama serve
ollama pull qwen3:8b
ankou paper.pdf -i "…" -p ollama

# smaller model? give it smaller windows
ankou paper.pdf -i "…" -p ollama \
  -m llama3.1:8b --window 8000

No key, no cost, no network egress. A daemon that answers but rejects a request is told apart from one that is not there at all — the first can be asked a different way, the second cannot, and collapsing the two only buys a worse error message later.

Settings

Flags beat environment beats file

A config file is a convenience and never a surprise. It lives at ~/.config/ankou/config.json — XDG_CONFIG_HOME is honoured — and a broken one warns rather than stops, but does not sit there being silently ignored. A key you mistyped gets the nearest real one suggested back. 

{
  "provider": "ollama",
  "model": "qwen3:8b",
  "renderer": "html",
  "theme": "auto",
  "open": true,
  "outDir": "~/reading",
  "windowChars": 12000
}

ANKOU_PROVIDER and ANKOU_MODEL cover the environment layer; -p, -m and --base-url cover the flags.

Everything else

Any model with a complete

If your model is behind a gateway, a queue, or a company proxy, implement the interface and pass it in. structured is optional: omit it and ankou prompts for JSON, validates against the schema, and retries once with the validator's own errors — which is enough for most models. 

import type { LLM } from 'ankou-core'

const myModel: LLM = {
  name: 'my-gateway:some-model',
  async complete({ system, prompt, maxTokens, temperature, signal }) {
    return await callMyGateway({ system, prompt, maxTokens, temperature, signal })
  },
}

await carve({ sources, intent, llm: myModel })

The built-in providers are exported too, if you would rather configure one and reuse it: anthropic(), openai(), ollama(), claudeCode().

This is also how you make ankou bill through your agent's model →

Structured output, whatever the provider. Every generation in ankou fills a JSON Schema. Where the provider supports tool use or a native schema mode, ankou uses it; where it does not, the output is parsed, validated in-tree, and handed back once with the errors it made. The format decides the schema — the provider only decides how it gets filled.
